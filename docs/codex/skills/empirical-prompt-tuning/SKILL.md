# 経験的プロンプト調整

独立した実行者が指示を正しく理解して実行できるかを検証し、指示を改善するためのワークフローです。

## 使う場面

- Codex プレイブック、スキル、プロンプトを作成または改訂する場合。
- 曖昧なタスク指示を引き締める場合。
- 指示が解釈のぶれではなく、予測可能な行動につながるか確認する場合。

通常の実装タスクにはこのワークフローを使用しません。

## ワークフロー

1. 現実的なシナリオを 2 つまたは 3 つ定義します。
2. 各シナリオについて、期待される挙動、必要な出力、失敗条件を特定します。
3. アクティブな Codex 実行環境が委任作業を許可し、かつユーザーが明示的に依頼している場合は、独立した実行者にシナリオの評価または実行を依頼します。
4. 委任が許可されていない場合は、代わりに静的な構造レビューを行い、その旨を明記します。
5. 明確性、完全性、実行可能性、失敗時の扱いを採点します。
6. 指示を修正します。
7. 残る問題が軽微になるか、これ以上の反復コストが正当化できなくなるまで繰り返します。

## 評価観点

- `clarity`: 実行者が隠れた前提なしに何をすべきか判断できる。
- `completeness`: 必要な入力、出力、制約、エッジケースが揃っている。
- `actionability`: 手順が実行できるだけ具体的である。
- `safety`: 指示が Codex 実行時ポリシーと衝突する行動を促していない。
- `fit`: ワークフローがリポジトリとユーザーの意図に合っている。

各観点に `Pass`、`Partial`、`Fail` を付け、根拠を 1 文で添えます。

## 出力テンプレート

```markdown
# プロンプト調整メモ

## 対象
<評価対象のファイルまたは指示>

## シナリオ
- <シナリオ>

## 所見
| 観点 | 結果 | 根拠 |
| --- | --- | --- |

## 修正
- <具体的な変更>

## 残存リスク
<短いメモ>
```

## Codex 実行時メモ

サブエージェントは任意であり、アクティブな実行ポリシーが許可し、かつユーザーが委任または並列エージェント作業を明示的に依頼した場合にのみ使用できます。それ以外の場合はローカルで作業し、評価は静的レビューだったと明記します。
