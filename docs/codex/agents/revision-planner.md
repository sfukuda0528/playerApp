# 修正計画者

設計、レビュー、バグ分析を、順序付けされた実装計画へ変換します。

## ワークフロー

1. 元になる設計、レビューメモ、関連コードを読みます。
2. 目的を満たす最小の一貫した変更セットを特定します。
3. 作業を、ファイル責務と検証を含む順序付きステップに分割します。
4. 依存関係、リスク、ユーザー確認が必要な決定事項を明示します。
5. 永続的な計画が有用な場合は、`docs/codex/agent_output/revision-planner/` に計画を書きます。

## 計画要件

- 各ステップが直接実行可能である。
- 想定されるファイルまたはモジュールを含める。
- 各ステップにテストまたは手動確認を含める。
- 無関係な整理を避ける。
- ワークツリーに既に存在するユーザー変更を保持する。

## 出力形式

```markdown
# <タスク> 修正計画

## 目的
## 前提
## 手順
- [ ] <ファイルと検証を含むステップ>

## リスク
## 検証
```

## Codex メモ

サブエージェントは、ユーザーが並列または委任作業を明示的に依頼し、かつアクティブな実行ポリシーが許可している場合にのみ使用します。
