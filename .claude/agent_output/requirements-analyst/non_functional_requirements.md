# 非機能要件詳細

## NFR-001: 写真同期レイテンシ

| 項目 | 内容 |
|------|------|
| ID | NFR-001 |
| 区分 | リアルタイム性 |
| 優先度 | High |
| 要件 | スマートフォンからの写真アップロード完了後、メインディスプレイのスライドショーへの反映まで2秒以内 |
| 根拠 | 「ラグなし」という明示的なコンセプト要件 |
| 計測方法 | アップロード完了イベント〜スライドショー画面更新のE2E時間測定 |
| 備考 | ネットワーク環境（グランピング施設のWi-Fi）に依存する部分あり。アプリ側の処理遅延を最小化する |

---

## NFR-002: Supabase依存可用性

| 項目 | 内容 |
|------|------|
| ID | NFR-002 |
| 区分 | 可用性 |
| 優先度 | Medium |
| 要件 | Supabase SLA（99.9%）の範囲内で継続稼働。独自サーバー不使用のためSupabase障害時はサービス停止を許容 |
| 根拠 | BaaS専用構成（CON-002） |
| 備考 | Supabase Realtimeの接続断時は自動再接続を実装する。障害時のユーザー向けエラーメッセージ表示が必要 |

---

## NFR-003: 同時接続数

| 項目 | 内容 |
|------|------|
| ID | NFR-003 |
| 区分 | スケーラビリティ |
| 優先度 | Medium |
| 要件 | 1セッションあたり最大10人の同時WebSocket接続を安定サポート |
| 根拠 | 想定ユーザー規模「4人程度」（CON-007）。余裕を持って10人を上限とする |
| 備考 | Supabase Realtimeの同時接続制限（プランによる）の確認が必要 |

---

## NFR-004: 音声再生品質

| 項目 | 内容 |
|------|------|
| ID | NFR-004 |
| 区分 | パフォーマンス |
| 優先度 | High |
| 要件 | 音楽と環境音のマルチトラック再生において、途切れ・ノイズ・遅延なく安定再生する |
| 根拠 | アンビエント・プレイヤーはコアUX（Key Features） |
| 計測方法 | 対象ブラウザ（Chrome/Safari/Firefox）での実機検証 |
| 備考 | iOS SafariはWeb Audio APIの自動再生制限あり。ユーザー操作起点での再生開始が必要 |

---

## NFR-005: ファイルアクセス制御

| 項目 | 内容 |
|------|------|
| ID | NFR-005 |
| 区分 | セキュリティ |
| 優先度 | High |
| 要件 | 写真・音楽ファイルおよびDBレコードへのアクセスを、同一セッションのメンバーのみに制限する |
| 根拠 | 他グループの個人写真・音楽への不正アクセス防止 |
| 実装方針 | Supabase Row Level Security（RLS）ポリシーでセッションIDによるアクセス制御 |
| 備考 | 認証方式（匿名認証等）の確定後に詳細設計が必要 |

---

## NFR-006: 型安全な実装

| 項目 | 内容 |
|------|------|
| ID | NFR-006 |
| 区分 | 保守性 |
| 優先度 | Medium |
| 要件 | TypeScriptのstrict modeを有効化し、型エラーなしでビルドが通る状態を維持する |
| 根拠 | Tech Stack（React + TypeScript）、長期保守性確保 |
| 実装方針 | `tsconfig.json`で`"strict": true`設定。SupabaseクライアントはDBスキーマから型自動生成 |

---

## NFR-007: 開発ビルド速度

| 項目 | 内容 |
|------|------|
| ID | NFR-007 |
| 区分 | 開発体験 |
| 優先度 | Low |
| 要件 | ソースコード変更後のHMR（ホットモジュールリプレイスメント）反映を3秒以内とする |
| 根拠 | Tech Stack（Vite）による高速HMR |
| 備考 | プロダクションビルド速度は本要件の対象外 |

---

## NFR-008: モーメント・ログ永続保存

| 項目 | 内容 |
|------|------|
| ID | NFR-008 |
| 区分 | データ永続性 |
| 優先度 | Medium |
| 要件 | セッション終了後に生成されたモーメント・ログ（写真一覧・プレイリスト）をSupabase DBに永続保存し、後から閲覧できる |
| 根拠 | Key Features（モーメント・ログ） |
| 備考 | 保存期間・削除ポリシー・ストレージコスト上限は未確認（open_questions参照） |

---

## NFR-009: ファイルストレージ容量設計

| 項目 | 内容 |
|------|------|
| ID | NFR-009 |
| 区分 | ストレージ |
| 優先度 | Medium |
| 要件 | Supabase Storageの利用プラン上限内で1セッションの全アップロードを収容できる設計とする |
| 根拠 | Tech Stack（Supabase Storage） |
| 実装方針 | 写真アップロード時のリサイズ/圧縮処理、音楽ファイルのサイズ上限設定を検討 |
| 備考 | Supabase無料枠: Storage 1GB。有料プランへの移行基準を事前に定義する必要あり |
